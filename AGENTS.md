# Руководство для агентов

## Назначение проекта

Одностраничное браузерное приложение для тренировки устной части ОГЭ и ЕГЭ по английскому языку. Пользователь вводит шифр, выбирает тип экзамена и вариант, после чего приложение автоматически проводит его по заданиям: показывает материалы, воспроизводит аудио, отсчитывает время на подготовку и записывает ответы через микрофон. Готовые записи доступны для скачивания в нижней панели; на сервер они не отправляются.

Основной пользовательский сценарий:

`/login` → `/instructions` → `/exams` → `/exam/:id` → `/finish`.

## Технологии и команды

- Vue 3, Composition API и `<script setup>`.
- Vite 5, JavaScript ES modules.
- Vue Router 4 с HTML5 history.
- Pinia; хранилища описаны через Options API.
- Axios для получения вариантов экзамена.
- Bootstrap 5 и SCSS.
- Prettier: одинарные кавычки, `trailingComma: "es5"`.

```bash
npm ci                 # установка зависимостей по lock-файлу
npm run dev            # dev-сервер на 0.0.0.0
npm run build          # production-сборка в dist/
npm run preview        # локальный просмотр production-сборки
npm run format         # Prettier перезаписывает все файлы в src/
```

Автотестов, линтера и отдельной команды проверки форматирования нет. После изменений обязательно запускать `npm run build`; для ручной проверки медиафункций нужны разрешение на микрофон и безопасный контекст (`localhost` или HTTPS). Не добавлять тестовый или линтинговый стек без отдельного запроса. Чтобы не форматировать неизменённые файлы, для точечной проверки можно использовать `npx prettier --write <файлы>`.

## Структура

- `index.html` — корневой `#app` и конфигурация URL в `data-urls`.
- `src/main.js` — создание приложения, Pinia, роутера и глобальная регистрация layout-компонентов.
- `src/App.vue` — выбор layout по `route.meta.layout` и реакция на выход пользователя.
- `src/router/index.js` — маршруты и проверка приватности через `auth.isGuest`.
- `src/layouts/` — общие оболочки страниц; `DefaultLayout` дополнительно содержит нижнюю панель с записями.
- `src/views/LoginView.vue` — ввод шифра и выбор `oge`/`ege`; это не серверная аутентификация.
- `src/views/InstructionsView.vue` — инструкция, загрузка вариантов и проверка записи с микрофона.
- `src/views/ExamsView.vue` — список загруженных вариантов.
- `src/views/ExamView.vue` — конечный автомат экзамена, таймеры и создание аудиозаписей.
- `src/views/FinishView.vue` — завершение и выход.
- `src/components/ExamContentComponent.vue` — содержимое задания, изображения, вопросы, вложенные таймеры и аудио.
- `src/components/MicAlertComponent.vue` — запрос доступа к микрофону при монтировании layout.
- `src/components/FooterComponent.vue` — скачивание записей и выход.
- `src/store/` — состояние авторизации, экзамена, микрофона и уведомлений.
- `src/utils/index.js` — обёртка над `MediaRecorder` и форматирование времени.
- `src/assets/scss/app.scss` — глобальный импорт Bootstrap.
- `docs/` — старая готовая статическая сборка с медиафайлами, не исходники текущего Vite-приложения. Не редактировать её при изменениях в `src/`; актуальная сборка создаётся в `dist/`.

## Состояние и внешние данные

`useAuthStore` хранит `userCode`, `examType` (`oge` или `ege`) и `isGuest` только в памяти. Persist-адаптера нет: перезагрузка страницы возвращает пользователя на вход. Не принимать этот механизм за полноценную аутентификацию.

`useExamStore` при загрузке модуля читает JSON из `#app.dataset.urls`:

- `urls.exams` — endpoint списка вариантов;
- `urls.files` — базовый URL изображений и аудио.

В текущем `index.html` это `/site/download-data` и `/site/download-file`. Dev-сервер проксирует `/site/*` на `http://exams.local:8010`, удаляя префикс `/site`. Для локальной разработки с реальными данными этот backend должен быть доступен.

Список загружается запросом `GET ${itemsUrl}?type=${examType}` на странице инструкций. Ожидается массив вариантов примерно такой структуры:

```js
{
  num: 1,
  type: 'oge', // или 'ege'
  waitTime: 5,
  tasks: [
    {
      id: 1,
      title: '...',
      description: 'текст или имя аудиофайла описания',
      images: ['image.png'],
      questions: ['question text' /* или имя аудиофайла */],
      prepareTime: 90,
      recordTime: 120,
      audio: false,
      selectableImages: false,
      sequentialQuestions: false,
      questionsInterval: 20,
      note: '...'
    }
  ]
}
```

Не все поля обязательны для каждого типа задания. При `audio: true` значения `description` и первого элемента `questions` используются как имена файлов относительно `fileUrl`. При `sequentialQuestions: true` вопросы показываются по одному с отдельным таймером. При `selectableImages: true` пользователь выбирает одно изображение.

## Логика проведения экзамена

В `ExamView.vue` каждое задание проходит три шага, закодированные через `step`:

1. `currSubTaskNum === 0` — пауза/ожидание между заданиями (`waitTime`).
2. `currSubTaskNum === 1` — подготовка (`prepareTime`).
3. `currSubTaskNum === 2` — запись ответа (`recordTime`).

Номер задания вычисляется как `Math.ceil(step / 3)`. Автоматическое завершение и кнопка досрочного завершения используют общий метод `stop()`. После записи создаются Blob URL и имя файла `${examType}._Задание_${id}._${userCode}.wav`; записи накапливаются в `exam.records` и отображаются в `FooterComponent`. Фактические данные создаются `MediaRecorder` с типом `audio/webm`, несмотря на расширение `.wav` — учитывать это при изменении формата записи.

`ExamContentComponent.vue` имеет собственный таймер последовательных вопросов. Не смешивать его с основным таймером экзамена. Аудио описания запускается при монтировании компонента, аудио вопросов — при переходе к записи.

## Правила внесения изменений

- Сохранять существующие идиомы Vue и Pinia, alias `@` для `src` и `~bootstrap` для Bootstrap.
- Пользовательский интерфейс и сообщения об ошибках — на русском языке.
- Для реактивного доступа к полям Pinia использовать `storeToRefs`, как в текущем коде.
- Новые приватные маршруты помечать `meta.isPrivate` и задавать `meta.layout`; публичные — `meta.isPublic`.
- Не переносить состояние экзамена в локальные компоненты, если оно нужно нижней панели или другим страницам.
- При изменении state machine проверять автоматические и досрочные переходы, последнее задание, отсутствие микрофона и скачивание всех записей.
- При изменении контракта вариантов синхронно проверять `ExamView.vue` и `ExamContentComponent.vue`.
- Не добавлять отправку записей или персонального шифра на сервер без явного требования.
- Не исправлять попутно старые дефекты и не менять `docs/`, если это не входит в задачу.
